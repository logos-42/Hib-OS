## 版本 0.2.1（2026-11-14）

本次是一个「修 bug + 提速」版本。用大白话说：**以前你在命令行里敲的几个符号其实没真正干活，界面也不会自己更新，现在都修好了**；另外把两个最常用的共享柜子换成了「允许多人同时读」的锁，系统更流畅。

### 修好的问题

| 编号 | 以前的样子 | 现在的样子 |
|---|---|---|
| UX-001 | `|`、`>`、`>>`、`<`、`&&`、`\|\|`、`;`、`&` 只是被识别，输出根本传不过去 | 全部真正生效：管道传内容、重定向写文件、条件链看上一条成败、后台作业可查询 |
| UX-002 | 只有 4 条命令支持 `--json` | 任意命令都能加 `--json`，返回统一的机器可读结果 |
| UX-003 | 按 Tab 只能补命令名 | 还能补子命令、选项、通道名、路径，输入时提示行直接列出候选 |
| PERF-001/002 | 能力注册表、文件系统用「一次只准一个人进门」的锁 | 改成 `RwLock`：多人同时查表互不等待，只有写才排队 |
| ARCH-002 | 界面每 400ms 无条件重画一遍（费 CPU 且最多慢半拍） | 界面订阅系统事件总线，**有事才刷新**，其余时间不画 |
| ARCH-003 | 「启动 Agent」在命令行、界面、能力接口三条路行为不一致 | 三条入口共用同一个 `agent::start`，结果、状态、事件完全一致 |

### 命令行新语法（怎么用）

```text
echo hello | grep hello              # 管道：左边说的内容传给右边筛选
echo 第一行 > /tmp/a.txt              # 覆盖写文件
echo 第二行 >> /tmp/a.txt             # 追加写文件
cat < /tmp/a.txt                     # 从文件读进命令
true && echo 成功                     # 上一条成功才执行下一条
false || echo 兜底                    # 上一条失败才执行下一条
pwd; ls                              # 分号：不管成败都继续
sleep 100 &  ...  jobs               # & 放后台，jobs 查结果
ls --json                            # 任意命令输出机器可读 JSON
```

打个比方：管道就像**传纸条**，前一个人写的内容原封不动递给后一个人；重定向就像**把纸条抄进笔记本**（`>` 是新本子，`>>` 是接在旧本子后面）。

### 新增命令一览

| 命令 | 参数 | 作用 | 返回值 / 退出码 |
|---|---|---|---|
| `echo` | `<文本...>` | 打印一行文本，常作管道数据源 | 成功 |
| `true` / `false` | 无 | 专门用来测试 `&&`、`\|\|` | 成功 / 失败 |
| `sleep` | `<毫秒>`（上限 2000） | 等待一会儿 | 成功 |
| `grep` | `<关键字>` | 从管道输入里挑出含关键字的行 | 找到=成功，没找到=失败 |
| `wc` | 无 | 数出上游的「行数 词数 字节数」 | 成功 |
| `head` / `tail` | `[行数]`（默认 10） | 取上游前 / 后几行 | 成功 |
| `sort` / `uniq` | 无 | 排序 / 相邻去重 | 成功 |
| `jobs` | 无 | 列出所有 `&` 后台作业及输出 | 成功 |
| `--json` | 任意命令后追加 | 输出 `{"command":...,"ok":...,"output":...}`（已有结构化输出的命令保持自己的格式） | — |

### 开发者注意

- **解析器只有一个**：`kernel/shell_parser.rs` 是唯一真相；`kernel/shell.rs` 只做 `pub use` 转发，不再有第二套解析逻辑。中文参数按字符切分，不会乱码。
- **输出捕获**：`sh_println!` / `sh_print!` 替代了 `println!` / `print!`，通过线程局部缓冲区收集输出，所以管道和重定向拿到的是真实内容。新加命令时务必使用这两个宏。
- **读写锁**：`capability_registry()` 返回 `RwLock`，读用 `read()` / `with_registry_read()`，注册才用 `write()`；`Vfs` 同理（`with_vfs_read` / `with_vfs_write`）。
- **GUI 刷新**：`gui::init_event_subscription()` 在启动时注册订阅者；`refresh_live_if_dirty()` 只在 EventBus 有变化时重画。窗口事件循环保留 120ms 心跳用于唤醒线程，但心跳本身不重画。
- **版本号**：`Cargo.toml` 与 `kernel/Cargo.toml` 必须一致，`tests/version_consistency.rs` 会检查；运行期版本由 `env!("CARGO_PKG_VERSION")` 派生，不要再硬编码。

### 本轮复盘与改进建议

- 根因集中在「**同一件事有三套实现**」：两套解析器、三条 Agent 启动路径、GUI 靠自己轮询。以后新增功能前先找有没有现成实现，能复用就别复制。
- 输出不可捕获是管道失效的隐藏原因：任何直接写屏幕的代码都会让管道拿到空串。建议加一条 CI 检查，禁止在 `kernel/shell.rs` 里出现裸 `println!`。
- Windows 上遗留的 `cargo test` 进程会锁住测试可执行文件，导致 `LNK1104` 链接失败；遇到时可换 `CARGO_TARGET_DIR` 或结束卡住的测试进程，不是代码问题。
- 后续可考虑：给 `&&`/`||` 加括号分组、支持 `2>` 标准错误重定向、把后台作业做成真正的可 `fg`/`kill` 作业控制。
