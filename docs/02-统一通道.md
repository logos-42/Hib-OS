# 统一感知层与通道

## 设计核心

内核里所有资源都是**通道**，地址形如 `<scheme>://<resource>`，对外只有两个动词：

| 动词 | 作用 | 需要的权限 |
|---|---|---|
| `sense <通道>` | 读取通道的实时快照 | 可读 (r) |
| `act <通道> [负载...]` | 向通道写入或触发一次操作 | 可写 (w) |

`channels` 命令列出全部 **107** 个通道、类别、读写权限以及感知/行动计数。

## 通道注册表

新增模块的标准步骤（无需改动 shell）：

1. 新建 `kernel/xxx.rs`，暴露 `xxx() -> &'static Mutex<Xxx>`，实现 `status()` 与各 `act` 方法；
2. 在 `kernel/channels.rs` 的 `bootstrap()` 注册通道 URI 与权限；
3. 在 `kernel/sense.rs` 的 `probe` 与 `act` 加一条分支；
4. 在 `kernel/mod.rs` 声明模块。

需要跨模块读取时直接锁对方的全局单例即可。注意保持单向依赖，避免两个模块互相加锁造成死锁。

若引入新的通道类别，还需同步 `ChannelKind::name()` 与 `ai_token.rs` 中的感知映射。

## 实时生成应用通道（AppGen）

| 通道 | 示例 | 说明 |
|---|---|---|
| `app/runtime` | `act app/runtime generate 做一个番茄钟` | 一句话需求当场生成应用说明书，返回专属通道 |
| `app/runtime` | `sense app/runtime` | 在线应用数、生成/拒绝/调用/热替换/销毁计数与最近审计 |
| `app/app-<序号>` | `sense app/app-1` | 单个生成应用的说明书摘要与运行状态 |
| `app/app-<序号>` | `act app/app-1 invoke echo 你好` | 只执行说明书声明过的白名单动作 |

`app/app-<序号>` 不是写死在 `bootstrap()` 里的，而是应用注册后由 Shell 的
`ensure_dynamic_channel()` 按需开通（与 `plugin/<name>` 同一套机制）；应用销毁后通道随之失效。
