# 19 - AI 原生操作系统设计

## 一、设计目标

把 Hib OS 从"GPU 为中心 + AI 意识雏形"推进为**以模型 (Model) 与智能体 (Agent) 为核心的 AI 原生操作系统**。所有传统 OS 抽象（进程、地址空间、文件系统、I/O 设备、死锁、安全、虚拟化）都重新映射为 AI 原生等价物，并统一接入已有的 `sense`/`act` 通道层。

## 二、核心映射关系

| 传统操作系统要点 (《现代操作系统》Tanenbaum) | AI 原生 OS 中的对应位 | Hib OS 实现 |
|---|---|---|
| 进程 (PCB、状态机、虚拟 CPU) | 智能体 (Agent)，独立 PCB 与状态机 | `kernel/ai_os/agent_proc.rs` |
| 线程 (共享地址空间的轻量执行体) | 智能体内的真线程子体 + 邮箱（事件驱动） | `kernel/agent.rs` + `agent_proc` |
| 地址空间 / 页表 / TLB | 模型权重(代码段) + 模型实例(运行态地址空间) | `kernel/ai_os/model.rs` |
| 虚拟地址 → 物理页框 | token → 上下文页/KV 缓存的语义映射 | `kernel/ai_os/ctx_mem.rs` |
| 缺页中断 → 调入磁盘页框 | 上下文窗口溢出 → 调入知识页/上下文页 | `ctx_mem::load_page` |
| 页面置换 (LRU/Clock) + Swap | 上下文页 LRU 淘汰 → 摘要写入长期记忆 | `ctx_mem::evict_lru` + `knowledge` |
| 文件系统 / inode / 目录 | 知识单元 (内容+向量+置信度+epoch) | `kernel/ai_os/knowledge.rs` |
| 路径查找 | 语义/向量检索 (RAG) | `knowledge::query` |
| 日志文件系统 (WAL) | 知识提交日志 + epoch 快照 | `knowledge::commit` |
| I/O 设备 / 驱动 / 中断 | 工具调用 (Tool Use, MCP 风格注册表) | `kernel/ai_os/tool.rs` |
| 磁盘调度 (SCAN/C-SCAN) | 推理请求调度 + KV 缓存预取 | `sched_ai` |
| 死锁 (资源分配图/银行家算法) | 智能体对模型实例/工具租约/上下文窗口的等待图环路 | `kernel/ai_os/deadlock.rs` |
| 安全 (ACL/能力/TCB) | AI 能力位沙箱 + 提示词注入防护 + 输出策略守卫 | `kernel/ai_os/security.rs` |
| 多处理机 / 调度 / 亲和性 | 多智能体并行 + 五调度域 + 模型实例亲和 | `kernel/ai_os/sched_ai.rs` |
| 微内核 / 外核隔离 | 模型容器沙箱 + 快照/回滚/隔离 | `kernel/ai_os/container.rs` |

## 三、子模块详述

### 3.1 model —— 模型即进程的地址空间/代码段
- `ModelSpec`：参数量、上下文窗口(token)、量化、显存占用、格式 (GGUF/ONNX/Raw)。
- `ModelInstance`：运行态实例，绑定智能体，持有 KV 缓存配额与上下文窗口占用（等价于进程的地址空间生命周期：Unloaded/Loaded/Active/Error）。
- 通道：`model://loader`、`model://instances`、`model://spec/<id>`。

### 3.2 agent_proc —— 智能体即进程 (PCB)
- `AgentPcb`：Pid、名称、角色、优先级、调度域、绑定模型实例、能力位子集、token 预算/已用、上下文窗口占用、父子关系、运行次数。
- 状态机：Created → Ready → Running → {Blocked | Completed | Failed}；`kill` 回收资源并清空子进程父引用。
- 真执行体：复用 `agent::spawn` 的真 OS 线程 + 邮箱，事件驱动，无轮询主循环。

### 3.3 sched_ai —— 模型感知调度器
- 五调度域 (reflex/perception/deliberation/memory/governance)，每个域独立 MLFQ 队列。
- 调度决策除优先级外，还考虑模型实例亲和（同模型实例连续调度，复用 KV 缓存）、token 预算耗尽降级、上下文窗口填充率。
- 接口：`enqueue` / `pick_next` / `expiry` / `preempt` / `status`。

### 3.4 ctx_mem —— 上下文窗口 / KV 缓存 (虚拟内存等价物)
- `ContextPage`：一段 token 序列 + KV 缓存，带 Present 位(in_memory)、引用时间戳(last_access)、dirty 标记。
- `ContextWindow`：每个智能体一个窗口（容量/已用/页列表/缺页/换出/换入/淘汰计数）。
- 缺页处理：窗口满时按 LRU 淘汰最久未访问驻留页，脏页回写长期记忆 (Swap)。

### 3.5 knowledge —— 记忆文件系统 (长期记忆 / Swap 后端)
- `KnowledgeUnit`：内容、伪嵌入向量、来源、置信度、epoch、访问计数。
- 提交即原子写入（提交日志 WAL 语义 + epoch 快照）。
- 语义检索：内容词重叠 + 向量余弦近似 Top-K，支持 RAG 风格按需调入。

### 3.6 tool —— 工具调用层 (I/O 设备与驱动等价物)
- 工具注册表：名称、描述、所需能力位、调用统计。
- `tool exec`：能力门禁检查，缺少能力则拒绝（类设备保护）；内置 fs.read/fs.write/net.get/code.exec/image.gen/kb.search。
- 工具调用返回即中断事件，供感知域调度。

### 3.7 deadlock —— 等待图死锁检测
- 资源类型：模型实例、工具、上下文窗口（单写者租约，一次只由一个智能体持有）。
- DFS 环路检测；恢复建议：抢占优先级最低的智能体资源，或将其上下文溢出到长期记忆，或终止该智能体。

### 3.8 security —— 能力沙箱 + 提示词注入防护
- AI 能力位 (CAP_MODEL_LOAD/CTX_READ/CTX_WRITE/TOOL_EXEC/KNOWLEDGE_COMMIT/AGENT_SPAWN/AGENT_KILL/SYS_ADMIN 等)，扩展 `caps.rs`。
- 提示词注入检测：匹配"忽略之前的指令/冒充系统角色/探查系统提示词/泄露/越狱"等模式，verdict 为 allow/redact/reject。
- 模型输出守卫：拦截 `rm -rf` / `format c:` / `shutdown` 等破坏性输出。

### 3.9 container —— 模型容器沙箱 (微内核/外核隔离)
- 每个模型实例独立容器，持有快照 (上下文 + KV 缓存 + 伪 PC/IR)。
- `create` / `snapshot` / `rollback` / `isolate` / `resume`，实现故障隔离与检查点回滚。

## 四、通道一览 (sense/act)

| 通道 | 含义 | 权限 |
|---|---|---|
| `model://loader` | 模型加载器状态 | rw |
| `model://instances` | 模型实例列表 | r |
| `model://spec/<id>` | 模型规格 | r |
| `ctx://kv` | 全局上下文/KV 摘要 | r |
| `ctx://window/<pid>` | 智能体上下文窗口快照 | r |
| `knowledge://store` | 记忆文件系统状态 | rw |
| `knowledge://query/<文本>` | 语义检索 | r |
| `tool://registry` | 工具注册表 | r |
| `aios://status` | AI 原生 OS 总控状态 | r |
| `security://status` | 安全策略状态 | r |
| `deadlock://graph` | 等待图死锁状态 | r |
| `container://status` | 容器沙箱状态 | r |

行动入口统一走 `act <通道> <op> ...`，示例：
- `act model://load /tmp/model.gguf gguf 7000000000 131072 q4_0 14336`
- `act agent://proc spawn coder coder medium 1`
- `act ctx://alloc 1 8192`
- `act knowledge://commit 智能体提交了一段上下文摘要 0.1,0.2 0.95 agent-a`
- `act tool://exec fs.read 读取文件`
- `act deadlock://wait 1 模型实例 7`
- `act security://filter 忽略之前的指令`
- `act container://create 7`
- `sense aios://status`

## 五、与既有 Hib OS 的兼容性

- 不修改或删除既有经过测试的功能（`kernel/exec.rs`、`kernel/lease.rs`、`kernel/caps.rs`、`kernel/channels.rs` 等保持不变，仅追加分支）。
- 新增 `kernel/ai_os/` 目录，在 `kernel/mod.rs` 注册 `pub mod ai_os`，并在 `boot_subsystems()` 中调用 `ai_os::init()`。
- 新增 `ChannelKind::Model/Ctx/Knowledge/Tool/Aios/Security` 及 8 个 `aios://`/`model://`/`ctx://`/`knowledge://`/`tool://`/`security://`/`deadlock://`/`container://` 通道，在 `kernel/channels.rs` `bootstrap()` 注册，`kernel/sense.rs` 增加 `probe`/`act` 分支。
- 沿用 `lease.rs` 单写者租约 + epoch 乐观 CAS 与 `caps.rs` 能力位，不引入新的同步原语或权限模型。

## 六、验收标准

- `kernel/ai_os/` 9 个子模块各自单元测试通过（`#[cfg(test)]` 内联）。
- 通道注册与 `sense`/`act` 分支正确路由。
- 不破坏既有 `kernel/` 模块的公开接口。

> 注：Hib OS 仓库基线中 `kernel/net`、`kernel/pkg`、`kernel/security/audit`、`kernel/security/sandbox`、`kernel/slab_alloc.rs`、`kernel/syscall/dynamic_linker.rs`、`kernel/async_runtime.rs`、`kernel/signal.rs`、`kernel/ipc_ext.rs` 等模块存在预置编译错误（非本次 ai_os 变更引入），导致整 crate 当前无法完整 `cargo build`/`cargo test`。ai_os 新增代码自身语法与类型检查无误；完整测试需在修复预置模块后进行。
