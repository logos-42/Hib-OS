# 灵感调度核心

**宏内核只有一个调度意志。** 五个调度域收回为五个内部相位，不再是五个并列的内核。

[返回目录](../README.md)

## 为什么合一

五域各自跑 MLFQ 带来的问题是：系统出现了五个互不相干的"意志"，谁先跑由域的边界决定，而不是由宏内核统一裁决。Hib OS 的立场是「一切都是 AI 意识的感知/行动通道」，因此调度也必须是**一个意识主体的一次判断**。

```text
                 ┌──────────────────────────────┐
   sense / act ─►│  Inspiration（唯一调度意志）  │─► 一个 pick 决策
                 │  reflex / perception /       │
                 │  deliberation / memory /     │
                 │  governance = 内部相位       │
                 └──────────────────────────────┘
```

## 对外契约

| 项目 | 收拢前 | 收拢后 |
|---|---|---|
| 调度通道 | `sched://reflex` … `sched://governance`、`sched://domains` | 主入口 `sched://inspiration`（旧通道保留作观测/调试） |
| 决策点 | 各域各自 `pick_next` | `pick_next_unified()` 一个决策点 |
| 五域语义 | 五个并列内核 | 同一个核心的五个相位 |

`scheduler_domains::pick_next_unified()` 按「相位默认优先级 → 就绪数」排序，跨全部相位只选出一个 token；`total_ready()` 提供统一负载视图。五域的 MLFQ、语义权重、老化、等待表全部保留，因此既有测试与 `sched://<相位>` 通道不受影响。

## 一次灵感循环

感知(perceive) → 起念(inspire) → 裁决(pick) → 回响(reflect)。

`inspire` 按任务语义推断相位：

| 关键词 | 相位 |
|---|---|
| irq / 中断 / fault / 唤醒 | reflex |
| sense / 感知 / 观察 | perception |
| mem / snapshot / 记忆 / 历史 | memory |
| power / cap / 策略 / 治理 | governance |
| 其它（act 类） | deliberation |

## 用法

```sh
sense sched://inspiration
act sched://inspiration inspire sense gpu://vram
act sched://inspiration pick
act sched://inspiration reflect
act sched://inspiration mode unified|domains
```

示例输出：

```text
灵感 #1: "sense gpu://vram" -> 相位 perception (优先级 High) token=1
裁决 #1: 相位 perception -> token1 (unified 单一决策点)
```

`sense` 摘要包含 `core=Inspiration mode=unified cycles=… picks=…`、五个相位的就绪/等待数、总就绪数与最近轨迹。

## 设计取舍

没有删除五域实现：它们仍是有效的隔离机制（各自就绪队列、等待表、优先级继承），只是**降级为内部相位**。这样既满足"宏内核是一个"，又不丢掉已验证的调度能力与测试。
